# 城市排水防涝泵站运行与内涝处置管理平台

面向排水泵站台账、泵组运行、排水管网与检查井养护、水位雨量监测、内涝点处置、闸门调度与抢险队出动的一体化城市排水防涝运行管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `drainage-pump:entries` 这一项，或调用 `resetModule(模块)`。

## 内涝处置队列规则（`waterlog` + `rescueteam`）

暴雨多点同时积水时，内涝点处置不再靠电话协调，规则全部落在
`frontend/src/api/local-service.ts`（页面只渲染、不判断）：

- **单向状态机**：内涝点严格 `待处置 → 处置中 → 已退水`，不许跳级（待处置不能直接确认退水）；
  已退水即锁定，不能再退回处置中或改退水时间。
- **处置队列排序**：处置中始终排在最前（按到场时间先后）；待处置按积水深度降序，
  达到警戒（≥30cm 警戒、≥50cm 特急）的先派；已退水折叠进「已完成」一面。
- **重复上报合并**：同一「内涝编号」重复上报只留一条，第二次上报合并到原记录
  （刷新积水深度/影响范围、累计上报次数），不插新记录；合并不改变状态，
  已退水的点再上报也不会被复活。
- **派队规则**：深度定级别、范围定方向——≥50cm 派重型抢险队（交通场景一队、其余二队），
  ≥30cm 派交通保障抢险队/应急突击队并置顶，一般积水派交通保障、社区排水或街道小分队。
- **退水时间以现场为准**：确认退水时填现场报回时间，与系统记录不一致时以现场值覆盖，
  并在「退水时间依据」留痕（覆盖了哪个系统值）。
- **抢险队联动**：派出处置自动创建/推进一条「抢险中」任务；退水办结后对应队伍自动进入
  抢险队页的「待归队清单」，现场归队后「确认归队」办结
  （`待派队 → 抢险中 → 待归队 → 已归队`，同样不许跳级）。

规则回归验证（Node + esbuild，localStorage 打桩，覆盖上述全部场景）：

```bash
cd frontend
npm run verify:rules
```
